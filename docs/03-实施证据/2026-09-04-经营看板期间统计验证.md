# 经营看板：当前池子与期间新增分离

## 实施边界

- 当前池子仍为当前全部未结案商机，使用当前有效报价或原始预估；不会因切换月份变成历史快照。
- 本期新增按建档日期归期，读取创建事件初始金额；重新报价和结案不改变新增，历史金额缺失单独提示。
- UI 将池子放在周期选择上方；周期为本周、上周、按年份分组的月份下拉，默认当月；无任意范围输入和重复起止日期说明。
- 团队动态保持独立天/周范围；全局人员和大区权限不变。
- 复用已有事件数据，无 schema 改动、无数据库迁移、无历史数据回填。前后端需一同发布；旧版本 API 未提供概览新增指标，不应只部署新前端。

## 验证结果

- Web：20 项组件/逻辑测试通过，含新增周期转换及页面交互用例。
- API：2 项新增口径单元测试通过；独立新建 PostgreSQL 18.4 测试库完成全部现有迁移后，4 项 reporting 接口集成测试通过。
- Web 类型检查、API 类型检查、Web 生产构建、API 生产构建通过。Web 构建仍提示主 bundle 大于 500 kB，未在本次扩展打包优化。
- 未进行浏览器人工视觉验收；部署后建议检查管理概览与商机经营的池子、期间区域及月份列表在实际窗口宽度下的呈现。

重点断言：

1. 默认自然月，本周/上周/月份互斥；跨年周、闰年二月、上海业务时区及禁止未来月份。
2. 总池子在日期选择上方；团队页隐藏月份控件并请求自身范围。
3. 后发请求先返回时，先发请求不能覆盖新月份的数据。
4. 创建事件金额优先于预估和最新报价；估算旧记录可回退，金额未知者不冒充零金额或采用当前报价。
5. 已成交、丢单、需求消失仍保留在创建期间的新增数量与金额。
6. 改变期间不影响当前池子；重新报价影响当前池子，但不改写首次金额；零初始金额合法。

## 空白测试库的前置数据注意事项

一次 Windows 命令参数转发使原本限定 reporting 的测试实际执行了全量 API 用例，结果为 97 项通过、1 项 M4 创建商机返回 400。

检查到 M4 自身只调用 `seedAccounts()`，而商机创建需要已启用的 `opportunity_source` 字典。另建隔离库完成迁移，再显式执行 `seedDimensions()` 后，M4 的 9 项用例全部通过。说明该用例在空白库存在基础字典初始化依赖，不据此判定报表改动破坏了商机创建。

本次没有更改 M4 业务代码或放宽字典校验，也不宣称未补前置数据的全量测试已全部通过。后续独立运行 M4/全量集成测试，应确保专用测试库包含必要基础字典，不依赖其他测试文件的运行顺序。

所有数据库验证均使用随机本机端口和新建的临时 PostgreSQL 集群；环境变量显式指向临时库，验证结束已停库。未连接本地 CRM 或云端业务库。临时验证脚本位于已忽略目录，不提交 Git。
