# CRM 业务收口临时排期

> 用途：集中记录本轮已确认但尚未全部落地的问题，完成一项即勾选并补充验证结果。全部收口后，将稳定结论归并至 `PRD.md`、`重构架构决策与实施蓝图.md`、`交互设计打磨.md`，本文件不作为长期规格。

## 一、收口原则

- 先修正业务事实与状态模型，再调整接口和页面，避免前端用固定标签猜业务过程。
- 用户填写的业务日期只精确到天；系统创建、修改、审批和归属操作时间精确到秒。
- 桌面端与移动端复用领域命令、校验和表单内容，不通过跳转整个页面实现表单复用。
- 客户、商机和计划的历史事实追加留痕；当前状态是投影，不覆盖历史。
- Excel 冷启动导入不伪造商机、报价或成交明细。

## 二、实施顺序与验收口径

### P0-A 客户生命周期与冷启动导入

- [x] 客户增加“CRM 启用前已成交”历史事实标记。
- [x] 客户增加可空的 CRM 前累计成交金额；金额未知与金额为 0 严格区分。
- [x] 客户经营阶段由系统计算为“潜在客户 / 本期新客 / 存量客户”，不保留 `history_unknown`，不允许销售直接编辑新老客户状态。
- [x] Excel 导入支持批次默认属性：存量成交客户、潜在客户、逐行指定。
- [x] Excel 导入支持最小客户资料、负责人/公海去向、字段映射、硬查重、疑似重复预览、错误行结果和批次审计。
- [x] 导入客户不要求必须存在联系人；日常手工建档仍保留联系人校验。
- [x] 客户列表和详情显示经营阶段；历史导入金额与 CRM 成交金额分开呈现。

### P0-B 客户归属与状态事件

- [x] 将单纯 `customer_transfers` 语义扩展为明确的归属与状态事件。
- [x] 事件明确区分：负责人移交、释放公海、公海认领、标记无效、恢复无效、接管审批通过。
- [x] 记录前后客户状态、前后负责人、操作人、原因和系统操作时间。
- [x] 成功发生的归属与状态变化进入客户 Timeline；申请拒绝、撤回等未改变客户事实的流程仍留在审批记录中。
- [x] 权限能力至少能区分释放、标记无效和恢复；销售只能释放本人客户到公海，区域负责人在管理范围内可标记无效，管理员可处理全部。

### P0-C 业务日期语义统一

- [x] 计划日、拜访日、商机跟进日、报价日、下单日、客诉业务日和下一行动日统一为日期语义。
- [x] API 使用 `YYYY-MM-DD`，数据库业务日期使用 `date`；`createdAt/updatedAt` 等审计字段继续使用时间戳。
- [x] 逾期规则统一为“计划日期早于今天”，当天计划不因虚构的 09:00 被判逾期。
- [x] 桌面端使用 Element Plus 日期组件；移动端使用 Vant 日期组件或基于其封装的薄组件，不自造日历控件。
- [x] Timeline 默认只显示业务日期；同日多条事实按系统创建时间稳定排序。

### P1-A 桌面端填报交互

- [x] 周视图点击计划或新增记录时留在周视图，通过弹窗/抽屉完成填报。
- [x] 复用领域服务、校验和表单组件，不通过跳转客户详情页复用整个页面。
- [x] 执行计划后原计划保留并变灰；实际记录只读；下一次行动形成新计划。
- [x] 连续编排一周计划时，保存后保持当前周和当前日期上下文。

### P1-B 移动端费用与客户列表

- [x] “我的”增加费用管理入口，不增加第五个底部主导航。
- [x] 费用页面继续使用既有填报能力，并确认列表按月份和分页/合理范围加载。
- [x] 客户列表保留每页 20 条无限滚动；增加失败提示与重试，失败不能伪装为“没有更多了”。
- [x] 支持下拉刷新并保持搜索条件。

### P1-C 移动端计划视图

- [x] 默认“日程”视图：顶部七日摘要条，下方只展开选中日。
- [x] 支持点击日期和左右切换；新增记录自动带入选中日期。
- [x] 增加“周概览”：按日显示计划、已执行、临时记录和客诉数量，用于排期比较与复盘。
- [x] 单日详情分为待执行、已记录和客诉；已执行计划以灰色状态保留。
- [x] 逾期待执行保持独立入口，避免挤占普通单日内容。

### P1-D 商机动态历程

- [x] 删除客户详情中固定的“发现需求 / 跟进 / 报价 / 下一步”四格假流程。
- [x] 后端生成商机动态活动投影：发现需求、每次跟进、口头报价、正式报价、成交、丢单、需求消失。
- [x] 客户详情的商机卡显示“当前状态 + 最近 3—5 个真实节点 + 下一步计划”。
- [x] 下一步计划与已发生事实视觉分离；开放商机无计划时明确提示。
- [x] 商机详情展示完整动态 Timeline，桌面端和移动端复用同一投影。

## 三、暂不纳入本轮

- 精确到小时的预约日历；如未来确有预约需求，单独增加可选时间段，不恢复全局时间选择。
- 历史订单或历史商机明细迁移；冷启动只保留存量成交事实和可选累计金额。
- `history_unknown` 长期状态。
- 移动端三日并排时间网格；当前采用七日摘要、单日详情和周概览。
- 管理看板视觉升级；继续优先完成 M0—M5 业务闭环。
