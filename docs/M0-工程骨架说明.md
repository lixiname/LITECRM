# M0 工程骨架说明：从空 template 到可运行 monorepo

> **本文是一条可照做的流水线**：先花 3 分钟读【〇 全貌】建立整体感，然后按【一 搭建】十步执行（每步三行：做什么 / 为什么 / 怎么做），最后用【二 验收】确认全绿。
> 配套阅读：`docs/重构架构决策与实施蓝图.md`（技术规格与决策依据）。

---

## 〇、全貌：3 分钟看懂这套东西

### 0.1 你要得到什么

一个 6 包 3 端的 pnpm + turbo monorepo：

```
apps/{web 桌面后台·ElementPlus / mobile 移动填报·Vant / api 后端·NestJS}
packages/{tsconfig / eslint-config / design-tokens / contracts / domain}
根：turbo.json + 门禁 + 环境 + CI
```

三句话概括架构：

- **一库锁版本**：pnpm 单 lockfile 锁全部依赖
- **链路管契约**：后端 DTO → Swagger → 前端类型，单向自动生成
- **门禁管质量**：lint / type / test / build + git 钩子，坏东西进不来

### 0.2 一条主线：先搭管道，再灌内容

```
空 template
 ├─① 版本控制   ② 工程中枢   ③ 规则(tsconfig)   ④ 规范(eslint)
 ├─⑤ 主题(design-tokens)   ⑥ 三应用骨架   ⑦ 契约管道   ⑧ 数据管道
 ├─⑨ 环境兜底   ⑩ 门禁+CI
现在 ──► M1 起填充业务：DTO、业务表、domain、业务模块
```

**规律：管道（配置/链路）先立，内容（业务代码）后灌。** 契约、DB、门禁都是先有管道后有数据。

### 0.3 十个坑（这套东西存在的理由）

| 没有它                  | 会踩的坑                      |
| ----------------------- | ----------------------------- |
| workspace + 单 lockfile | 6 包各自 install，版本满天飞  |
| 共享 tsconfig           | 三端严格度不一致，A 能过 B 挂 |
| 共享 eslint-config      | 三端风格漂移                  |
| design-tokens           | 两端色值各写各的              |
| 契约链路                | 后端改字段，前端类型不知道    |
| domain 层               | 页面直接 fetch，URL 散落      |
| turbo                   | build 顺序靠手动              |
| 门禁                    | 坏代码进 git，历史不可回溯    |
| docker + env + README   | 换机器起不来                  |
| CI                      | 本地过远端挂，无人兜底        |

### 0.4 四条链（架构的骨架）

| 链     | 一句话                                                               |
| ------ | -------------------------------------------------------------------- |
| 依赖链 | pnpm 单 lockfile + 符号链接，改共享包立即生效                        |
| 任务链 | turbo 按依赖顺序执行 + 缓存                                          |
| 契约链 | DTO → Swagger → openapi.json → openapi-typescript → contracts → 前端 |
| 质量链 | husky → lint-staged → commitlint → CI                                |

## 一、搭建：十步照做

> 执行约定：**先建文件，后装依赖**（依赖安装在步 10 后统一做）。每步按做什么 / 为什么 / 怎么做理解。

### 准备 · 前置环境

| 工具    | 要求                | 备注                                   |
| ------- | ------------------- | -------------------------------------- |
| Node.js | ≥20.19（建议 22.x） | `.nvmrc` 锁                            |
| pnpm    | 11.x                | `corepack enable`                      |
| Docker  | 任意近期版本        | 本地数据库**二选一**：Docker 或本机 PG |

### 步 1 · 版本控制

- **做什么**：`git init` + `.gitignore` + `.nvmrc`
- **为什么**：一切改动可回溯；先有地基再盖楼
- **怎么做**：`.gitignore` 必含 `node_modules/` `dist/` `coverage/` `.env` `.env.*`（保留 `!.env.example`）`*.local`；`.nvmrc` 写 `22`

### 步 2 · 工程中枢

- **做什么**：`pnpm-workspace.yaml` + 根 `package.json` + `turbo.json`
- **为什么**：pnpm 认识仓库（哪些目录是包）、turbo 编排任务、根命令当总入口——一键起的前提
- **怎么做**：
  - `pnpm-workspace.yaml`：`packages: [''apps/*'', ''packages/*'']`
  - 根 `package.json` scripts **必含**（缺一条 = 该命令没入口）：
    ```json
    "dev:web": "pnpm --filter @crm/web dev",
    "dev:mobile": "pnpm --filter @crm/mobile dev",
    "dev:api": "pnpm --filter @crm/api start:dev",
    "build": "turbo build",
    "test": "turbo test",
    "lint": "turbo lint",
    "typecheck": "turbo typecheck",
    "contracts:generate": "pnpm --filter @crm/api generate:openapi && pnpm --filter @crm/contracts generate",
    "contracts:check": "pnpm --filter @crm/contracts check",
    "db:generate": "pnpm --filter @crm/api db:generate",
    "db:migrate": "pnpm --filter @crm/api db:migrate",
    "db:studio": "pnpm --filter @crm/api db:studio",
    "prepare": "husky"
    ```
  - `turbo.json`（2.x 用 `tasks`）：`build.dependsOn: [''^build'']` + `outputs: [''dist/**'']`

### 步 3 · 规则单源（共享 tsconfig）

- **做什么**：`packages/tsconfig`（base / node / vue 三份）
- **为什么**：三端严格度一致；改一处全生效
- **怎么做**：
  - `base.json`：strict + moduleResolution bundler
  - `node.json`（api 用）：commonjs + node 类型
  - `vue.json`（双端用）：DOM 类型 + jsx preserve
  - api `tsconfig.json` extends **用相对路径**（别用包名，不依赖 pnpm 链接）：`../../packages/tsconfig/node.json`

### 步 4 · 规范单源（共享 eslint）

- **做什么**：`packages/eslint-config`（index.mjs）+ 根 `eslint.config.mjs` + `.prettierrc`
- **为什么**：三端 lint 规则只写一遍；风格统一
- **怎么做**：
  - `index.mjs` 组装 6 个成熟库（@eslint/js、typescript-eslint、eslint-plugin-vue、vue-eslint-parser、eslint-config-prettier、globals），导出 flat config **数组**
  - 根 `eslint.config.mjs` 一行：`import config from ''@crm/eslint-config''; export default config`
  - **workspace 引用必须声明**（pnpm 严格隔离，不声明就找不到）：根 devDeps 加 `@crm/eslint-config: workspace:*`；`apps/api` devDeps 同样加

### 步 5 · 主题单源（design-tokens）

- **做什么**：`packages/design-tokens`（tokens.ts + tokens.css）
- **为什么**：双端（EP/Vant）色值只此一份
- **怎么做**：
  - `tokens.ts` 导出常量对象；`tokens.css` 定义 `:root` 的 `--crm-*` 变量
  - 两端 `main.ts` `import ''@crm/design-tokens/tokens.css''`
  - **web/mobile deps 加 `@crm/design-tokens: workspace:*`**

### 步 6 · 三应用骨架

- **做什么**：web（ElementPlus）、mobile（Vant）、api（NestJS）骨架
- **为什么**：让三个应用能起、能测、能 lint——业务有处跑
- **怎么做**：
  - **web/mobile 各建**：`main.ts`（挂 UI 库 + pinia + router）、`router/index.ts`、`pages/HomePage.vue`、`vite.config.ts`（端口 5173/5174 + `@` 别名）、`vitest.config.ts`、`tsconfig.app.json`
  - **web/mobile scripts 必含**（缺了 turbo 门禁会**跳过**它们，等于没验证）：
    ```json
    "dev": "vite",
    "build": "vue-tsc -b && vite build",
    "preview": "vite preview",
    "test": "vitest run",
    "typecheck": "vue-tsc -b",
    "lint": "eslint src --fix"
    ```
  - `tsconfig.app.json` 配 `paths` **不加 baseUrl**（TS6 已弃用）：`"paths": { "@/*": ["./src/*"] }`
  - **api 建**：`main.ts`（`setGlobalPrefix(''api'')` + 全局 ValidationPipe + Swagger）、`eslint.config.mjs`（引共享包）、`vitest.config.ts`、`tsconfig.json`（相对路径 extends）

### 步 7 · 契约管道

- **做什么**：api 的 Swagger 出 `openapi.json` → openapi-typescript 生成契约类型
- **为什么**：后端 DTO 是唯一事实源，前端类型永远跟随后端（防漂移）
- **怎么做**：
  - `apps/api/scripts/generate-openapi.ts`：`NestFactory.create` → `SwaggerModule.createDocument` → 写 `packages/contracts/openapi.json`
  - `packages/contracts` scripts：`generate`（openapi-typescript -o src/generated/api.ts）+ `check`（`--verify` 无 diff）
  - api scripts 加 `"generate:openapi": "ts-node scripts/generate-openapi.ts"`

### 步 8 · 数据管道（drizzle 占位）

- **做什么**：`drizzle.config.ts` + `src/common/db/schema/index.ts`（空占位）+ `src/common/db/db.ts`
- **为什么**：先把水管接好——M1 建表只需填内容（表定义），不用回头重配
- **怎么做**：
  - `drizzle.config.ts`：dialect postgresql + schema 指向 index.ts + dbCredentials 走 env
  - `schema/index.ts`：`export {}` 占位
  - `db.ts`：`drizzle(new Pool({ connectionString: DATABASE_URL }))`——**惰性连接**，不执行 SQL 不连库，api 启动无副作用

### 步 9 · 环境兜底

- **做什么**：`.env.example` + `docker-compose.yml` + `README.md` + `.github/workflows/ci.yml`
- **为什么**：换机器可跑、异地有兜底
- **怎么做**：
  - **本地数据库二选一**（PG16+，含 pg_trgm 扩展）：
    - **Docker（推荐，环境一致）**：`docker-compose.yml` 定义 postgres:16，`docker compose up -d db` 即可
    - **本机已装 PostgreSQL**：三条命令**分开跑**（别用 `psql -c "A; B;"`，见踩坑表）：
      ```bash
      psql -U postgres -c "CREATE USER crm WITH PASSWORD 'crm_dev_password';"
      psql -U postgres -c "CREATE DATABASE litecrm OWNER crm;"
      psql -U postgres -d litecrm -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"
      ```
  - `.env.example`：DATABASE_URL / JWT_SECRET / PORT；Windows 本机 PostgreSQL 常占用 5432，因此 Docker 开发库固定发布到 `localhost:5433/litecrm`
  - `ci.yml`：install → migrate → lint → typecheck → test → build → contracts:check；PostgreSQL service 是空库，测试前必须显式执行迁移

### 步 10 · 门禁

- **做什么**：husky + lint-staged + commitlint
- **为什么**：把规范变成强制（靠自觉迟早失守）
- **怎么做**：
  - `.husky/pre-commit`：`pnpm lint-staged`；`.husky/commit-msg`：`pnpm commitlint --edit "$1"`
  - 根 scripts 的 `"prepare": "husky"` 让 install 时自动激活钩子
  - `lint-staged.config.mjs`：`*.{ts,vue,mjs}` → eslint --fix + prettier --write
  - `commitlint.config.mjs`：extends conventional

### 依赖安装（十步文件建完后，根目录执行）

```bash
# ① 根工具链（必须先装！--ignore-scripts：husky 未装时 prepare 会失败）
pnpm add -wD --ignore-scripts eslint prettier husky lint-staged @commitlint/cli @commitlint/config-conventional
# ② 共享 eslint-config 依赖
pnpm --filter @crm/eslint-config add --ignore-scripts typescript-eslint eslint-plugin-vue vue-eslint-parser eslint-config-prettier @eslint/js globals
# ③ 前端运行时
pnpm --filter @crm/web add element-plus pinia vue-router
pnpm --filter @crm/mobile add vant@4 pinia vue-router
# ④ 前端测试
pnpm --filter @crm/web add -D vitest @vue/test-utils jsdom
pnpm --filter @crm/mobile add -D vitest @vue/test-utils jsdom
# ⑤ api 运行时
pnpm --filter @crm/api add drizzle-orm pg @nestjs/config class-validator class-transformer @nestjs/swagger @nestjs/jwt bcryptjs @nestjs/event-emitter
# ⑥ api 开发依赖
pnpm --filter @crm/api add -D drizzle-kit vitest supertest @types/pg @types/supertest openapi-typescript
# ⑦ contracts 契约生成
pnpm --filter @crm/contracts add -D openapi-typescript
# ⑧ 清理 Nest 骨架自带旧测试 + 冗余 lint
pnpm --filter @crm/api remove jest ts-jest @types/jest eslint prettier @eslint/js @eslint/eslintrc eslint-config-prettier eslint-plugin-prettier globals typescript-eslint
# ⑨ 构建脚本审批 + 链接 + 激活钩子
pnpm approve-builds && pnpm install && pnpm prepare
```

> ⚠️ 步 2/4/5 若已声明 `workspace:*`，⑨ 的 `pnpm install` 会让链接生效。不想交互可手动写 `pnpm-workspace.yaml`：`esbuild: true`（平台二进制）、`''@scarf/scarf'': false`（遥测）。

### 踩坑速查（十步中可能踩的坑）

| 坑                        | 正确做法                                                                                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| prepare 鸡生蛋            | husky 未装时任何 pnpm 命令会因 `prepare: husky` 失败 → 第①步必须 `--ignore-scripts`                                                                                                |
| eslint 版本               | 直接用最新（10+）：typescript-eslint / eslint-plugin-vue / vue-eslint-parser 均已支持 eslint 10                                                                                    |
| @types/bcryptjs           | bcryptjs 3.x 自带 TS 类型，不要装 @types/bcryptjs（已弃用）                                                                                                                        |
| Nest 自带 Jest            | 换 Vitest 后必须移除 jest/ts-jest/@types/jest（否则引入 unrs-resolver 构建脚本）                                                                                                   |
| api 自带 eslint 全家桶    | 共享配置包接管后，api 里 eslint/prettier/globals/typescript-eslint 全是冗余，移除                                                                                                  |
| 传递依赖 deprecated       | glob/inflight/esbuild 多版本等警告来自上游，无权升级，忽略                                                                                                                         |
| workspace 包互引          | 跨包 import 必须声明 `workspace:*`，否则 pnpm 不链接、运行时找不到                                                                                                                 |
| tsconfig extends          | 共享 tsconfig 用相对路径（`../../packages/tsconfig/node.json`）                                                                                                                    |
| TypeScript 6 弃用 baseUrl | paths 已支持相对解析，加 baseUrl 会直接报错                                                                                                                                        |
| 前端漏 scripts            | web/mobile 缺 test/typecheck/lint 会被 turbo 门禁**跳过**（等于没验证）                                                                                                            |
| vitest.config ESM 警告    | api 是 CommonJS，vitest 提示配置用 ESM；无害，可改名 vitest.config.mts 消除                                                                                                        |
| web chunk >500KB          | Element Plus 全量引入所致，仅警告；M1 可做按需引入                                                                                                                                 |
| git LF/CRLF 警告          | Windows 下 core.autocrlf 提示；无害，可选加 .gitattributes（`* text=auto`）                                                                                                        |
| Docker WSL2 代理          | daemon.json 手写 `127.0.0.1` 代理在 WSL2 虚拟机内**不可达**（VM 的 127.0.0.1 不是宿主机）→ 会堵死引擎；改用 DaoCloud 镜像加速，或走 Docker Desktop GUI 的 Resources→Proxies 配代理 |
| psql -c 多语句事务        | `psql -c "A; B;"` 是**隐式事务**，任一语句失败则全部回滚（含已成功的）→ 建库/建用户必须一条一个 `-c`                                                                               |
| CI 报 relation 不存在     | CI 数据库是全新实例，`beforeAll` 的 seed 不负责建表 → 在 test 前增加 migrate，不要在测试代码里临时创建业务表                                                                       |
| gin_trgm_ops 不存在       | 三元组索引依赖 `pg_trgm` → 首份迁移先执行 `CREATE EXTENSION IF NOT EXISTS pg_trgm`；普通数据库账号无权限时由管理员预装扩展                                                         |
| 旧库迁移成功、空库失败    | 旧库可能已经人工安装扩展或保留历史对象 → 迁移验收必须同时覆盖“已有库增量升级”和“空库从 0 执行全部迁移”                                                                             |
| Windows 迁移命令 ENOMEM   | drizzle-kit 若报 `uv_os_get_passwd ... ENOMEM` → 使用 `pnpm --filter @crm/api db:migrate:runtime` 执行相同 SQL；禁止改用自动同步绕开迁移                                           |

## 五、FAQ

**为什么前端拆成 web + mobile 两个应用？** 桌面用 Element Plus、移动用 Vant，UI 体系/路由/页面都不同；但业务逻辑共享——公共部分放 packages/domain，两个应用只放各自的皮。

**为什么 API 不用 Jest（Nest 自带）？** 规格定前后端统一 Vitest。顺带好处：去掉 Jest 后不再引入 unrs-resolver 原生构建脚本，pnpm approve-builds 的警告也随之消失。

**契约链路是不是太绕？** 绕一次，省一劳。前端手写类型时后端改字段 90% 不会同步；契约生成让类型永远跟随后端，且 CI 强制无 diff。

**没有 CI 能不能先跑？** 能。本地 pnpm lint/typecheck/test/build 与 CI 同一套检查；ci.yml 只是搬到远端兜底。

**这些配置能砍掉哪些？** 硬性必需：turbo.json、eslint+prettier、pnpm-workspace.yaml+lockfile、共享 tsconfig。协作护栏（单人可后置）：husky/commitlint/CI/docker-compose——建议保留，越早养成习惯成本越低。
