# 交互设计打磨（UX · 功能如何呈现、UI 如何衔接）

> **定位**：与 PRD 互补——PRD 定"做什么、功能点"，本文定"**如何呈现、页面间如何衔接**"。
> **核心**：个人行动周视图是移动端主界面的设计主干；历史拜访/跟进是事实时间线，未来行动是唯一待办来源，两者不复制。
> 配套：`docs/PRD.md`（功能点/验收）、`docs/技术打磨清单.md`（实现健壮性）。
> **设计基线**：历史事实与未来行动分开展示；用户从行动进入业务执行，完成后回到来源上下文并看到最新状态。

---

## 1. 交互设计基线（跨模块通用）

### 1.1 页面分区（详情页三段式）

```
PageHeader（标题 + 主操作区，主操作靠右）
  ├─ 主信息区（谁/是什么：名称、等级、状态、负责人）
  ├─ 业务操作区（记录入口：记拜访/建商机/登客诉 → 明显可点）
  └─ 时间线区（历史活动：按时间聚合，只读）
```

**原则**：主操作一眼可见；危险操作（释放/结案/作废）与主操作视觉分离（红/灰）；编辑等次要操作收敛到"更多"或图标。

### 1.2 操作组织

- **主操作**（主色）：新建、提交、认领
- **次要操作**（灰/描边）：编辑、移交、申请接管
- **危险操作**（红色/描边）：释放、结案、作废、停用 → 必须弹确认 + 说明后果
- 入口按能力点显隐（`hasAbility`），无权限不渲染

### 1.3 衔接原则

| 场景                         | 衔接方式                                                               |
| ---------------------------- | ---------------------------------------------------------------------- |
| 列表 → 详情                  | 行点击跳详情（web）；卡片点击（mobile）                                |
| 详情 → 填报表单              | **弹窗/抽屉（web）或 push 页面（mobile）**，完成后返回详情并刷新时间线 |
| 表单提交成功                 | toast + 返回来源页 + 目标页刷新（红线 11，不整页刷新）                 |
| 弹窗类操作（移交/接管/释放） | 弹窗内完成 → 关闭 → 详情局部刷新（`reload`），不跳走                   |
| 返回                         | mobile `router.back()`；web 详情页"返回列表"（保持查询上下文，后置）   |

### 1.4 双端一致性

- 重合功能（客户详情/表单）**结构对齐**：mobile 的"快速登记"组 ↔ web 的"业务操作区"必须同构（§5.4 schema 共享）；
- 差异只在形态（web 弹窗 vs mobile 整页 push），**功能入口一个不少**。

## 2. 个人行动：周视图（核心界面）

> 心智：**行动清单 / 日历**——pending 是要做的，completed 是已完成，cancelled 是明确不做；历史拜访和商机跟进回到各自时间线查看。
> 呼应蓝图：§8.7 行动唯一事实源、§8.10 日 card 待办聚合、§8.4/8.5 业务记录与下一步行动联动。

### 2.1 定位

- **移动端主界面**：销售打开看“今天/本周要做什么、哪些已经逾期”（P0 体验核心）；
- **桌面端“行动”页**：侧边栏入口，个人视角；管理聚合另行设计。

### 2.2 移动端周览（单列日 card 流）

- 布局：周选择器 + **7 张日 card 纵向滚动**；默认定位今天，今天高亮
- 每张 card 只呈现行动，按来源标识：手工 / 拜访 / 商机 / 客诉
- pending 可完成、改期、取消；completed/cancelled 置灰保留；**早于当前范围仍未完成的行动固定在顶部逾期区**
- 空 card 有“+ 加行动”；点行动 → 进入对应客户/商机/客诉的执行入口，并带上 `sourceActionId`
- 单列适合单手滑动，一屏 1~2 天

### 2.3 桌面端周览（横向周网格）

- 布局：周选择器 + **7 列网格（一屏一周）**，周一~周日横排
- 每列显示行动卡片，以来源色标和状态区分；**hover 预览、点击抽屉处理**
- 大屏可统计 pending/completed/cancelled，并通过行动来源查看实际拜访或跟进，不靠文本做模糊配对
- 历史已完成行动只读；pending 可编辑；逾期标红，与移动端一致

### 2.4 计划与记录分流（关键原则）

| 动作                   | 思维                      | 交互                                   |
| ---------------------- | ------------------------- | -------------------------------------- |
| **加行动**（未来）     | “哪天做什么” → **按日期** | 日历式：点某天空白 → 快速加手工行动    |
| **记事实**（已经发生） | “刚做了什么” → **按内容** | 类型驱动：走拜访/商机跟进/客诉处理入口 |

> 加行动=按天思维；记记录=按内容思维。记录提交时可以完成来源行动，并按需创建下一步行动；周视图始终只查询行动。

### 2.5 联动落位

| 动作               | 落位                                                          |
| ------------------ | ------------------------------------------------------------- |
| 拜访填写下一步     | 创建来源为 visit 的行动，落到 plannedAt 对应日 card           |
| 商机跟进填写下一步 | 完成来源行动并创建来源为 opportunity_follow_up 的新行动       |
| 商机报价填写下一步 | 完成来源行动并创建来源为 opportunity_quote 的报价后反馈行动   |
| 客诉跟进填写下一步 | 完成来源行动并创建来源为 complaint_follow_up 的新行动         |
| 行动执行           | 点行动 → 进入对应执行表单，预填客户/商机并携带 sourceActionId |
| 完成/改期/取消     | 更新同一行动；不新增或复制另一条“周计划项”                    |

## 3. 填报便利性（移动端，P0）

### 3.1 默认今天

- 周览默认定位今天；"记一笔"默认今天；表单日期字段默认今天
- 改日期是**例外动作**，不打断"打开即填"

### 3.2 补录快捷（外勤刚需）

- 日期字段提供 **"昨天 / 今天 / 明天"快捷按钮**，点一下切换，不翻日历
- 覆盖"现场没空记、晚上补录"的高频场景

### 3.3 多入口预填

| 入口            | 预填          |
| --------------- | ------------- |
| Tabbar·记一笔   | 默认今天      |
| 周览·某天分区   | 该日期        |
| 客户详情·记拜访 | 该客户 + 今天 |

### 3.4 轻量表单

- mobile 只留必填（客户 + 时间 + 方式 + 一句话），复杂字段收起
- 呼应 P0"顺手快不打断"

## 4. 填报入口（类型面板 · 学 Tabbar）

### 4.1 移动端"记一笔"Tab

- 快捷面板：**拜访 / 商机 / 客诉**三大按钮 + 顶部默认日期（可切昨今天），点哪个进哪个表单（超兔式：意图直接）

### 4.2 桌面端填报入口

- 周视图空白处点击 → **快速加行动**（预填日期）；记录业务事实仍走对应模块表单
- 侧边栏各模块列表的"新建"按钮（类型入口）
- 客户详情"记拜访"（预填客户）

## 5. 支撑模块 · 客户管理链路

### 5.1 客户列表

- 呈现：卡片式/表格均可用；关键列（名称/城市/等级/状态/负责人）；状态用色块标签
- 衔接：点行 → 详情；"新建客户"主按钮（`customer.write`）

### 5.2 新建客户（查重弹窗交互）

- 流程：填名称+电话 → 提交时**静默查重**：
  - 硬拦截 → 直接报"已存在"，禁止继续
  - 疑似 → 弹窗列出疑似客户（名称+城市+置信度徽标），三个动作：**查看疑似 / 继续新建 / 申请接管**
- 衔接：继续新建 → 原表单保留不丢失；成功后跳详情
- 内联建档：客户选择器搜不到 → 当前表单内展开快速建档（名称+电话），不跳页

### 5.3 客户详情设计约束

| 必须满足的设计     | 应避免的反模式                                                       |
| ------------------ | -------------------------------------------------------------------- |
| 业务记录入口       | 详情只提供移交、释放等治理操作，却不能记拜访、建商机或登记客诉       |
| 面向人的移交选择器 | 要求用户输入内部用户 ID，而不是按姓名、组织和角色选择负责人          |
| 聚合活动时间线     | 只展示基本资料和联系人，用户必须分别进入多个模块才能判断客户最新进展 |
| 明确的编辑入口     | 客户资料只能查看，或把编辑能力隐藏在与业务无关的位置                 |

**目标设计**：

```
头部：客户名（+ 状态/等级标签）     操作区：记拜访(主) | 商机 | 客诉 | 编辑 | 移交/接管/释放(危险)
基本信息卡：descriptions（名称/城市/产业/等级/状态/负责人/地址/备注）
业务操作区：三个记录入口卡片（图标+文案，mobile 已有，web 补齐）
联系人卡：列表 + 添加/编辑（首要联系人徽标）
时间线：拜访/商机/客诉按时间倒序聚合（类型图标 + 摘要 + 时间）
```

### 5.4 归属操作衔接

| 操作         | 交互设计                                                                          |
| ------------ | --------------------------------------------------------------------------------- |
| **移交**     | 弹窗：**用户选择器**（搜索显示名）+ 原因；确认后 toast + 详情刷新（负责人列变化） |
| **接管申请** | 弹窗：原因；提交后 toast + 提示"已提交审批"                                       |
| **释放**     | 确认弹窗：去向（公海/无效）+ 原因 + **后果说明**（未解决客诉拦截提示）            |
| **认领**     | 主按钮直接执行 + toast                                                            |

- 所有归属操作**弹窗内完成**，不跳走详情（衔接原则 1.3）

### 5.5 双端一致性验收清单

- ☐ web 详情补齐"业务操作区"（与 mobile"快速登记"同构）
- ☐ 移交选择器双端统一（web 弹窗 / mobile 弹层 picker）
- ☐ 时间线双端呈现（web 表格时间线 / mobile cell 列表）
- ☐ 归属操作双端入口一致（web 完整 / mobile 查看为主 + 关键操作）

## 6. 商机闭环（跟进、报价与明确下单）

### 6.1 定位

- 商机的核心是持续回答“最近发生了什么、现在有效报价是什么、下一步由谁何时做”；阶段看板是视图，不是唯一操作入口

### 6.2 桌面端：阶段看板

- 列：intent → following → won / lost / demand_disappeared（§8.5 状态机）
- 卡片：客户 + 名称 + 意向规模 + 最近报价 + 当前行动；行动逾期或无下一步时红标
- 点卡片 → 详情抽屉/页面，分开呈现“记跟进”“记口头报价”“登记正式报价”“确认下单”“结案”
- 拖拽为可选增强（小团队以按钮推进为主，不强制拖拽）

### 6.3 移动端：列表 + 详情推进

- 列表：按阶段筛选 / 逾期优先
- 详情：基本信息 + 跟进时间线 + 报价时间线 + 当前行动；操作按钮按业务事实分开，不用一个万能“推进”弹窗

### 6.4 逾期治理

- 逾期商机：当前行动逾期 → 红标/置顶；开放商机无 pending 行动 → “无下一步”；最近报价或跟进超过阈值 → “停滞”
- **点进去即处置**：完成/改期/新增行动，补跟进或明确结案；单纯查看不会自动改变状态

## 7. 客诉闭环（工单式 · 借鉴 Zendesk）

### 7.1 定位

- **待解决驱动**：客诉的价值在"解决"，界面围绕"还有哪些没解决 + 逾期"

### 7.2 列表

- 逾期 / 未解决优先排序，逾期红点
- 状态标签（registered / resolved）+ 解决后置灰

### 7.3 详情

- 问题描述 + 发生时间 + **跟进时间线（只追加）** + 当前处理行动
- 操作：跟进（内容必填；FOLLOWED_UP → 下一步行动；RESOLVED → 解决结果并取消剩余行动）
- 解决为终态，跟进入口置灰/拦截（§8.6）

### 7.4 联动

- 未解决 + 关联行动逾期 → 风险视图（§8.9 客户风险）

## 8. 费用（随手记 · 借鉴记账类应用）

### 8.1 定位

- 轻量统计，非报销（蓝图 §8.8）；"顺手记"不折腾

### 8.2 移动端：快速记一笔

- 默认今天 + 五类金额（烟酒/礼品/餐叙/招待/住宿）快速输入 + 备注 + 提交
- 同天再记 = 更新原记录（upsert，§8.8）

### 8.3 桌面端：月度列表 + 汇总

- 月度列表（按人/月/分项）；汇总卡（个人按日、团队按月）
- 三态可见：draft（草稿灰）/ submitted（计入）/ voided（剔除标灰留痕）

### 8.4 作废

- 确认弹窗："将不再计入统计，留痕可查" → 提交

## 9. 行动周视图（日历/任务式 · 借鉴 Todoist/滴答）

### 9.1 定位

- 行动管理 + 周目标/复盘 + 指导意见闭环；周视图不拥有第二份行动数据

### 9.2 行动管理

- 新增手工行动、完成、改期、取消；业务联动产生的行动显示来源并可回到来源记录

### 9.3 计划与完成情况（桌面）

- 周网格按行动状态统计 pending/completed/cancelled；通过 sourceActionId/sourceId 精确追溯实际拜访或跟进

### 9.4 指导意见

- 管理者 → 被指导者，**红点已读闭环**；author 须为被指导者上级（§8.7）

## 10. 登录 / 用户管理（标准 SaaS）

### 10.1 登录

- 标准登录页；会话保持（refresh 静默续期）；403 引导（无权限提示）
- 防爆破：错误 5 次锁定提示（后端语义，前端展示）

### 10.2 用户管理

- 表格 + 行操作（编辑 / 停用启用 / 重置密码），交互见 PRD §3
- 操作按 `user.manage` 显隐；停用/重置有确认 + 后果说明

### 10.3 字典配置

- 列表将“显示名称”和“字典值”并列展示：管理者看到中文业务含义，也能识别系统保存的稳定值
- 新增时两项均必填；字典值建议使用稳定英文标识，并明确提示其会被业务数据长期引用
- 编辑时字典值只读，只允许调整显示名称、排序和启停状态；确需替换稳定值时应新增新项并停用旧项
- 各业务表单只展示启用项及其显示名称；历史详情仍能解析已停用项，不直接向用户暴露英文值

## 11. 桌面工作台（Dashboard · 借鉴 HubSpot）

### 11.1 定位

- 桌面登录落地页；回答"今天要做什么、有什么风险"

### 11.2 组成

- **今日行动卡片**：今天的 pending 行动 + 更早逾期行动（红点，点击直达处置）
- **快捷入口**：记拜访 / 建商机 / 登客诉（customer.write）
- **风险提醒**：逾期客诉 / 大商机停滞（executive）
- **最近活动流**：最近的拜访/商机/客诉动态（时间线摘要）
