# CRM 项目立项 PRD（冻结版）：工业设备销售全过程CRM · M0-M5

> 版本：V0.1
> 目标：避免“建表后再补系统”，在开发前先定清“为什么做、做什么、做完何为验收”。

## 1. 项目边界（本批次冻结范围）

- 本次只执行 M0-M5。
- 本次不再单独追求：全面BI 管理看板、Open5000 双向接口的完整接入、复杂组织绩效模型。
- 本次目标是先把**可复用的销售闭环事实**打通：
  1. 客户画像与归属
  2. 拜访/商机/客诉/行动的关系可追踪
  3. 销售阶段与成交事实可确认
  4. 回款与订单先保留为下游系统输入，不进入 M0-M5 主干模型（仅保留接口位）

## 2. 当前关键问题（只保留可执行的“痛点翻译”）

1. 销售跟进事实在 Excel/口头记忆中断裂，管理层无法知道“是否在推进、卡在哪一环”。
2. 商机和客户有隔离感：客户看不到商机链路，商机看不到客户背景。
3. 回款/订单/发货属于后端财务流程，不与销售过程同一事实源。
4. 团队不信任重复填写，因为系统没把“最少一次动作”变成“最有用事实”。

## 3. 业务目标（管理层可验收）

- **目标A：把销售过程转成可追踪链路。**
  - 拜访、商机跟进、报价、客诉、未来行动都可见。
  - 任一商机必须有“当前下一行动”或明确结案。

- **目标B：消除“重复录入/不一致”。**
  - 销售过程事实（已发生）与未来行动只记录一份。
  - 引导并校验“报价后是否有客户反馈行动”，避免空悬意向。

- **目标C：管理者能看得见且可验真。**
  - 任何待办来源可回链到源对象（拜访/商机/客诉）。
  - 客户页可确认历史成交与在途商机，且不依赖手工周报。

## 4. 模型边界（先做不先想）

- **先建事实，不先建报表。**
  - 客户 = 组织承接单元
  - 拜访、商机、客诉 = 已发生事实
  - 行动（计划）= 当前待办
  - 成交（Deal）= 明确下单命令

- **字段策略**
  - 硬唯一：ERP 客户编码、统一社会信用代码（可空）。
  - 客户等级用于资源与策略，不与利润/财务口径混用。
  - `firstVisitedAt/firstDealAt/lastActivityAt`类派生值只有在有明确投影策略时才展示。

## 5. M0-M5 实施范围与交付标准

### M0：基础能力就绪

- 用户/权限可覆盖现场场景。
- 客户主数据可建档、查重、归属、联系人完整。
- 停止依赖周计划复制业务动作。

### M1：客户主视图闭环（优先）

- 客户详情新增三块：
  1. 最近/历史商机（含金额、阶段、下一行动）
  2. 历史成交摘要（最近成交金额、累计金额）
  3. 客户活动时间线（拜访、商机跟进、客诉）
- 商机列表带客户名与点击回链。
- 认领/移交/释放与未解决客诉约束。

### M2：商机主链路完整化

- 商机新建可指定来源客户。
- 商机新建覆盖来源、产品线、约估金额与说明、发现/预计成交日期和第一步行动；客户页与商机列表复用同一表单。
- 商机工作台可按客户/名称检索并按阶段、金额、报价、下一行动和停滞风险筛选；列表直接显示最近报价、最近跟进、当前行动与客户当前负责人。
- 商机跟进与多次报价（口头/正式）可追加。
- 报价后必须有下一步行动。
- 明确下单命令生成唯一 Deal。

### M3：客诉与风险闭环

- 客诉登记、跟进、解决动作与对应行动联动。
- 已解决客诉转入历史不可再执行有效跟进。

### M4：未来行动与周视图

- 行动按来源聚合展示。
- 完成/改期/取消后在全局一致。

### M5：验证与交付（上线前）

- 全量功能验收通过。
- 主要失败模式（空漏斗、重复信息、脱离行动）得到界面级阻断或告警。

## 6. 验收通过条件（冻结判定）

以下任一未通过，M0-M5 不得切到下一批次：

- 商机列表每条能看到客户名且可回链客户页。
- 开放商机无下一行动、行动逾期、超过 30 天未推进或预计成交日已过时，工作台可见并可筛选；该风险由业务事实派生而非手工维护。
- 客户页能看到商机列表、历史成交（至少最近一条金额）与活动时间线。
- 商机的“报价→后续行动”链条真实（有行动可见）。
- 管理员与销售都能按角色看到同一事实源，不出现“同一对象双写不一致”。
- 公开讨论材料可明确说明：M0-M5 不包含的项。

## 7. 下批次前提（M6+）

- Open5000 订单/出货/应收字段模型确认后，再启动回款-财务-库存闭环。
- 回款看板需要与该财务链路模型一并定义。
