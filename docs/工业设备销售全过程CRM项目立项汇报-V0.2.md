# 工业设备销售全过程 CRM 项目立项汇报

> 版本：V0.2（管理层讨论稿）
> 日期：2026 年 8 月 25 日
> 项目牵头及实施：内部自研，现阶段由项目负责人独立牵头业务调研、产品设计与开发
> 本次汇报目的：确认建设方向、首期边界、试点方式及管理配合事项

---

## 一、立项建议

建议公司启动销售全过程 CRM 项目，以客户和具体采购需求为主线，逐步贯通：

> 客户开发 → 拜访 → 下一步行动 → 商机 → 报价后跟进 → 下单 → 出货 → 回款

项目首先解决三个问题：

1. 销售每天在跟进哪些客户、下一步是什么，管理人员能够及时了解；
2. 报价形成的意向能够区分有效、停滞、暂停和丢失，销售漏斗不再长期失真；
3. 销售录入的信息能够反过来帮助本人工作，减少个人台账、人工周报和重复询问。

首期不建设复杂报价单生成、产品自动配置、ERP 替代或完整财务系统。先把销售过程跑通并验证使用效果，再逐步接入订单、出货和回款。

---

## 二、为什么需要建设

公司主营泵浦及成套过滤设备，面向 B2B 小型离散制造业客户销售，年经营规模约 6000 万元。销售团队约 20 人，按省区开展园区陌拜、老客户维护和展会获客，典型销售周期通常为 1 个月或更长。

管理层对当前问题已有基本认识，本项目需要重点解决的不是“有没有系统”，而是现有信息无法支持持续管理：

| 当前情况                                | 对经营管理的影响                           |
| --------------------------------------- | ------------------------------------------ |
| 客户资料分散在个人微信、旧 CRM 和旧 ERP | 客户历史不完整，人员协作和交接困难         |
| 拜访后没有稳定形成下一步行动            | 销售依赖个人记忆，管理层不知道每日推进情况 |
| 业助按正式或口头报价登记 Excel 意向台账 | 后续依赖人工询问销售，更新不及时           |
| 报价后一两个月没有进展也可能一直保留    | 意向池金额虚高，无法判断真实销售储备       |
| 销售填写 CRM 后对本人帮助不大           | 使用意愿低，个人小台账比系统更方便         |
| 周报和回款跟进依靠手工台账              | 重复劳动多，过程和结果不能围绕客户贯通     |

如果只增加填报要求，而不改变销售本人使用体验和管理方式，新系统仍可能重复旧 CRM 的结果。

## 三、行业调研结论与本项目取舍

### 1. 调研范围

前期已对 Salesforce、Microsoft Dynamics 365、SAP Sales Cloud、Oracle Sales、HubSpot、Zoho CRM、Pipedrive 和 Freshsales 等代表性 B2B CRM 进行了初步调研。调研不是为了照搬大型软件功能，而是识别成熟 CRM 长期稳定的产品骨架和移动端发展方向，避免内部设计偏离该类系统的基本规律。

完整材料见《[B2B CRM 全球代表产品、核心功能与移动端体验趋势调研](./B2B-CRM全球代表产品与移动端体验调研.md)》。

### 2. 成熟 B2B CRM 的共同骨架

不同产品面向的企业规模和行业不同，但核心能力高度一致：

| 行业共同能力             | 解决的问题                                 | 对本项目的意义                      |
| ------------------------ | ------------------------------------------ | ----------------------------------- |
| 客户与联系人主数据       | 统一企业、联系人、负责人和客户关系         | 建立客户长期经营基础                |
| 互动时间线               | 汇总拜访、电话、会议、邮件、笔记和状态变化 | 让销售与接手人员理解客户历史        |
| 商机与销售管道           | 管理阶段、金额、预计时间、输赢原因         | 形成可信的销售漏斗                  |
| 活动、任务和下一步行动   | 告诉销售当前应该做什么                     | 解决拜访后没有下一步的问题          |
| 报价、订单及外部系统衔接 | 将销售过程连接到经营结果                   | 与报价支持、ERP、出货和回款逐步贯通 |
| 权限、流程和审计         | 保证数据范围、责任和过程可追溯             | 适应按省区和小组管理的组织方式      |
| 预测与管理分析           | 观察储备、转化、周期、风险和结果           | 同时支持过程管理和结果统计          |
| 自动化与集成             | 减少重复录入和人工提醒                     | 避免 CRM 再次成为额外台账           |

由此可见，CRM 的基本方向不是“多存一些客户资料”，而是把客户、互动、商机和下一步行动串成可持续推进的销售过程。

### 3. 移动端和使用体验趋势

行业产品的移动端正在从“桌面系统缩小版”转向“销售任务工作台”，重点回答：今天要联系谁、哪些事项逾期、哪个商机有风险、刚完成的客户互动是否已经形成下一步。

对本项目最重要的产品原则包括：

- 移动端优先服务现场短任务，不追求复制桌面全部功能；
- 减少录入比增加字段更重要，常用动作应尽量短；
- 一次客户互动应自动产生时间线、下一步、提醒和汇总；
- 系统应主动提示逾期和风险，而不是等待管理人员人工翻表；
- 销售录入的信息应首先返回给销售本人使用；
- AI、语音和自动摘要可以降低录入成本，但应建立在结构化流程和可信数据之上，不能替代基础业务建设。

这些趋势与公司当前问题基本一致：销售缺少个人工作台和下一步提醒，管理层缺少过程可见性，业助和后台依赖人工台账协同。因此，本项目不是为了追赶某个软件的功能数量，而是用适合公司规模的方式落实成熟 CRM 的基本原则。

### 4. 结合公司业务的取舍

成熟 CRM 的完整能力很多，但不适合一次性全部纳入本项目。结合工业设备直销、约 20 人销售团队和单人自研条件，建议采取以下取舍：

| 业界常见能力                  | 本项目判断                                         |
| ----------------------------- | -------------------------------------------------- |
| 客户、互动、任务、商机和管道  | 属于 CRM 基础骨架，首期必须具备                    |
| 移动任务工作台和快速记录      | 直接决定销售是否愿意使用，首期重点                 |
| 报价与商机衔接                | 必须考虑，但首期只做轻量协同，不制作复杂报价单     |
| 订单、出货和回款              | 属于公司经营闭环，纳入总体蓝图并分阶段接入         |
| 线索管理                      | 展会场景可能需要，首期可先以客户/商机方式验证      |
| 邮件、日历、电话和钉钉集成    | 有助于减少录入，待核心流程稳定后建设               |
| 复杂产品配置、CPQ、合同和审批 | 价值存在但实施复杂，不进入首期                     |
| 全量离线、地图路线、签到      | 是否建设取决于真实外勤需求，不因行业产品具备就照搬 |
| AI 摘要、风险识别和智能录入   | 后置，先保证业务事实、状态和权限正确               |

因此，行业调研对本项目的作用是确定基本方向和设计原则，而不是扩大首期范围。内部需求决定优先解决什么，行业共识帮助判断解决方式是否完整、是否可持续。

## 四、准备建设什么

### 1. 销售个人工作台

销售打开系统后，应能直接看到：

- 今天需要跟进的客户；
- 已经逾期的下一步行动；
- 报价后长期没有反馈的商机；
- 本人客户的近期沟通历史；
- 后续接入的订单、出货和回款提醒。

系统首先帮助销售管理自己的客户和计划，然后再为管理层提供统计。

### 2. 客户拜访与下一步行动

拜访记录不只说明“做过什么”，还要形成下一步。常规场景只要求销售记录客户、本次结果、下一步事项和下一步日期。

一次记录自动进入客户历史、个人待办、周报和管理视图，原则上不再要求重复填写相同内容。

### 3. 可信的商机和意向池

客户的一次具体采购需求作为一条商机持续管理。系统需要区分：

- 待确认商机；
- 正常推进的有效商机；
- 已报价跟进；
- 长期无进展的停滞商机；
- 项目暂停或丢失；
- 已下单。

历史报价金额不能直接等同于有效意向金额。管理层应分别看到有效、待确认、停滞、暂停、丢失和成交金额。

### 4. 轻量报价协同

当前业助参与报价是由产品组合、价格和生产端信息复杂所决定，不是单纯的重复录入岗位。首期保持现有报价制作方式，CRM 只做必要衔接：

- 销售在商机中提出报价支持需求；
- 业助完成报价后确认“报价已完成”；
- 系统记录报价日期和必要金额，并生成销售后续跟进；
- 业助不再维护独立的 Excel 意向池；
- 首期不强制把报价文件上传 CRM，也不建设自动报价单。

### 5. 订单、出货和回款逐步闭环

对公司业务而言，下订单代表销售基本成功，出货代表确定性进一步提高，完成回款才形成经营闭环。

总体蓝图需要覆盖订单、出货和回款，但正式事实原则上以 ERP 或财务数据为准。首期先摸清现有数据和导出条件，采用最小可行方式让责任销售看到本人客户的订单、应收和逾期情况，后续再评估自动接口。

十多种付款方式可统一拆分为多个应收节点，例如预付款、发货款和验收尾款，不需要为每种合同单独开发一套流程。

## 五、项目建设原则

1. **销售本人先受益**：填写内容必须转化为本人可用的提醒、客户历史、进展查询或自动周报。
2. **一次录入，多处使用**：同一事实只维护一次，不把 Excel 台账原样搬进 CRM。
3. **下一步驱动**：进行中的客户和商机应有明确下一步；没有下一步时说明原因。
4. **异常优先**：管理层首先看到无下一步、逾期、停滞、高金额风险和回款异常，而不是只看累计数量。
5. **分阶段建设**：先解决销售过程，再扩展订单、回款和系统集成。
6. **不盲目替代现有系统**：CRM 不替代生产、ERP 和财务核算。
7. **管理方式同步调整**：系统已有的信息，原则上不再要求销售重复填写线下台账和周报。

## 六、建议建设范围

### 首期：解决销售过程不可见和意向池不可信

- 客户、联系人和负责人；
- 移动端客户查询与快速拜访记录；
- 下一步行动、今日待办和逾期提醒；
- 商机状态、有效性确认和停滞识别；
- 轻量报价协同；
- 销售个人客户时间线；
- 区域经理团队过程和异常清单；
- 自动周报草稿；
- 基础权限、区域范围和必要审计。

### 第二阶段：形成经营结果闭环

- 订单和出货状态；
- 应收计划、到期及逾期提醒；
- 销售查看本人客户回款；
- 管理层按地区、销售和客户查看订单及回款情况；
- 根据 ERP 条件采用录入、导入或接口同步。

### 后续优化

- ERP 自动集成；
- 报价支持流程深化；
- 产品配置、自动定价和报价单生成；
- 钉钉免登和消息提醒；
- 展会线索导入；
- 语音或文字快速记录；
- 经营预测与智能分析。

### 首期明确不做

- 完整替代 ERP、财务或生产系统；
- 复杂产品组合和自动定价；
- 在 CRM 内直接制作全部正式报价单；
- 一次性开发合同、订单、库存、开票和财务全模块；
- 未经业务验证的大量报表和 AI 功能。

## 七、前期工作基础

项目负责人已开展以下前期工作：

1. 对一个区域业务部门负责人进行了初步需求访谈；
2. 梳理了客户、拜访、商机、报价台账、周计划和回款等现状；
3. 完成了 B2B CRM 代表产品及移动端体验的初步调研；
4. 建立了 Lite CRM 探索性原型，已实现或验证客户、拜访、商机、权限、周计划、费用等部分思路；
5. 在进一步讨论中识别出原型对报价协同、订单、出货和回款覆盖不足，需要重新以业务蓝图校准范围。

Lite CRM 不作为管理层必须接受的既定方案，而作为前期调研、产品思考、技术验证和后续可复用资产。项目获批后，将依据批准的业务蓝图决定保留、调整或暂缓现有功能。

## 八、实施方式

### 1. 项目负责方式

现阶段由项目负责人统一承担：

- 业务调研牵头；
- 产品范围和流程整理；
- 原型及系统开发；
- 试点支持和问题收集；
- 文档及后续迭代维护。

这种方式沟通链路短、调整速度快，但也要求项目严格控制范围，并由管理层明确业务决策和验收责任。项目负责人可以牵头提出方案，但不宜独自替代销售、业助、后台/财务及管理层决定全部业务规则。

### 2. 业务配合方式

不建议成立复杂的专职项目组，但需要指定必要的业务联系人：

- 一名管理层决策人：处理跨部门和范围决策；
- 一名区域负责人或销售代表：验证销售过程；
- 一名业助代表：验证报价支持流程；
- 一名后台/财务代表：确认订单、出货和回款事实；
- ERP 相关联系人：确认数据导出和接口条件。

上述人员不需要全职参与，只需在访谈、规则确认、试用和验收节点提供反馈。

### 3. 试点方式

建议继续选择已参与初步访谈的区域，或选择业务量适中、负责人愿意配合的一个小组试点：

1. 先确认该区域真实销售流程和管理规则；
2. 只开发首期核心链路；
3. 使用真实业务开展试点；
4. 验证销售是否愿意使用、区域经理是否能够据此管理；
5. 达到使用和数据质量要求后，再逐步取消重复台账并推广。

### 4. 计划安排

在管理层确认首期范围和试点部门后，由项目负责人形成详细功能清单、迭代顺序和时间评估。现阶段不建议在业务边界尚未确认前承诺完整工期。

## 九、预期效果与验收方向

| 目标         | 验收方向                                                             |
| ------------ | -------------------------------------------------------------------- |
| 销售愿意使用 | 手机端常规拜访记录尽量在 30 秒内完成，填写后能直接形成待办和客户历史 |
| 跟进过程可见 | 活跃商机大部分具有下一步行动，区域经理能看到逾期和停滞事项           |
| 意向池可信   | 历史报价、待确认、有效、停滞和丢失金额分别统计                       |
| 减少重复劳动 | 试点稳定后取消重复意向 Excel 台账，周报主要由系统生成                |
| 管理真正使用 | 区域会议优先查看系统，不再重复询问系统中已有信息                     |
| 结果逐步闭环 | 后续阶段销售能够查看本人客户的订单、应收和逾期情况                   |

具体数值目标在试点开始前根据现有基线确定，避免在没有实际数据时制定失真的指标。

## 十、主要风险

| 风险                           | 控制方式                                         |
| ------------------------------ | ------------------------------------------------ |
| 功能范围过大，单人实施失控     | 严格分期，首期只做核心销售链路                   |
| 再次变成只服务管理层的填报系统 | 优先建设销售个人工作台和下一步提醒               |
| 系统与 Excel 长期并行          | 试点验收后由管理层明确取消重复台账               |
| 商机长期不更新                 | 设置有效性确认、停滞规则和经理异常清单           |
| 业务规则由开发人员单方面决定   | 指定业务联系人，在关键节点确认和验收             |
| ERP 数据条件不明确             | 先调研现有数据，首期采用最小衔接方案             |
| 已开发原型限制新方案           | 以批准后的业务蓝图为准，不因已有代码扩大首期范围 |

## 十一、本次需要管理层确认

建议管理层对以下事项给出原则性意见：

1. 是否同意启动销售全过程 CRM 项目；
2. 是否同意首期优先解决拜访下一步、商机有效性、报价后跟进和自动周报；
3. 是否同意订单、出货和回款纳入总体蓝图，分阶段实施；
4. 是否同意复杂报价制作和 ERP 深度集成不进入首期；
5. 是否同意选择一个区域或小组试点；
6. 是否指定管理层决策人及销售、业助、后台/财务联系人；
7. 是否同意试点稳定后逐步取消重复意向台账和手工周报；
8. 是否同意由项目负责人根据批准范围继续完成详细需求、原型调整、开发计划和试点实施。

## 十二、立项后的下一步

如管理层原则同意，建议按以下顺序推进：

1. 补充访谈销售、业助和后台/财务代表；
2. 确认商机阶段、停滞时间、经理介入和回款责任规则；
3. 摸清 ERP 的订单、出货、开票和回款数据条件；
4. 确定试点区域和首期验收指标；
5. 形成首期详细 PRD、原型和开发排期；
6. 依据新蓝图评估现有 Lite CRM 功能的复用和调整；
7. 开始小范围迭代和真实业务试点。
