# Lite CRM 产品需求明细（PRD）

> **文档定位**：产品需求明细——回答"做什么、用起来顺不顺"。与 `docs/重构架构决策与实施蓝图.md`（技术规格：怎么做、语义对不对）互补。
> **职责边界**：蓝图管语义与架构约束（数据/权限/流程规则）；**PRD 管页面清单、交互、反馈、验收标准**。
> **用途**：打磨的逐条依据——拿着 PRD 逐模块打勾，缺哪补哪；也是验收（M6+ 真机/演示）的检查单。

## 0. 文档约定

### 0.1 功能点字段模板

每个功能点按以下字段描述（无内容项默认省略）：

| 字段 | 说明                      |
| ---- | ------------------------- |
| 入口 | 从哪里进入                |
| 操作 | 用户操作步骤              |
| 校验 | 输入/状态约束             |
| 权限 | 能力点要求（无则"登录"）  |
| 边界 | 异常/临界情况处理         |
| 反馈 | UI 反馈（成功/失败/确认） |
| 验收 | 可验证的标准              |

### 0.2 通用交互规范（全局强制，所有页面遵守）

| 规范             | 要求                                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------------- |
| **三态统一**     | 加载中（loading/骨架屏）、空态（el-empty/van-empty + 文案）、错误态（提示 + 重试按钮）走共享组件，禁止各页手写 |
| **操作反馈**     | 写操作成功 → 全局消息（ElMessage/Toast）；失败 → 错误信息展示                                                  |
| **危险操作确认** | 删除/停用/作废/释放 → 确认弹窗，必须说明后果                                                                   |
| **提交链路**     | 提交按钮 loading + 防重复提交；成功后 `reload()`/`setData()` 刷新，**不整页刷新**（红线 11）                   |
| **权限 UI**      | 无能力点的入口/按钮不渲染（`hasAbility`），与路由守卫同源                                                      |
| **表单校验**     | 内联提示 + 提交拦截；必填项标 `*`                                                                              |
| **登录态**       | access 过期 401 → 统一跳登录，记录来源页，登录后回跳                                                           |

## 2. 身份与登录

### 2.1 登录页（web / mobile）

- **入口**：未登录访问任意页 → 重定向 `/login`
- **操作**：账号 + 密码 → 登录按钮
- **校验**：两项必填（非空）
- **边界**：防爆破（后端连续 5 次锁 15 分钟）；密码错误提示不区分"账号不存在/密码错"（防枚举）
- **反馈**：错误 → "账号或密码错误"；锁定 → "尝试次数过多，已锁定 15 分钟"；成功 → 跳落地页（web 客户列表 / mobile 客户 Tab）
- **验收**：正确登录进落地页；错误 5 次出现锁定提示；刷新后会话保持（refresh 静默续期，后置）

### 2.2 修改密码（本人）

- **入口**：我的 / 用户菜单 → 修改密码
- **操作**：旧密码 + 新密码（≥8 位）+ 确认
- **反馈**：成功 → 提示"密码已修改，请重新登录"，清 token 跳登录
- **验收**：改密后旧会话全部失效

## 3. 用户管理（admin · `user.manage`）

> 实现现状：3.1 列表雏形已有（缺搜索/筛选/行操作）；3.2-3.5 待实现（打磨项）

### 3.1 用户列表

- **入口**：侧边栏 → 用户管理
- **内容**：列 = 用户名 / 显示名 / 角色 / 上级 / 区域 / 状态 / 最近登录
- **操作**：搜索（用户名/显示名）、筛选（角色/状态）、分页
- **反馈**：加载中、空态（"暂无用户"）、错误态+重试
- **验收**：admin 可见该菜单；非 admin（如 executive）不可见

### 3.2 新建用户

- **入口**：列表 → "新建用户"按钮
- **字段**：用户名（唯一）、显示名、角色、上级（按组织树可选）、手机、区域、初始密码（≥8 位）
- **校验**：用户名查重（冲突提示"用户名已存在"）
- **反馈**：成功 → toast + 返回列表并刷新；失败 → 提示原因
- **验收**：创建后列表可见；重复用户名被拦截

### 3.3 编辑用户 ←（当前缺失，打磨项）

- **入口**：列表行 → "编辑"按钮（或详情操作）
- **可改**：显示名 / 角色 / 上级 / 手机 / 区域 / 状态
- **反馈**：成功 → toast + 列表刷新；改角色后该用户重新登录权限生效
- **验收**：改角色后该用户登录可见菜单/能力随之变化

### 3.4 停用 / 启用

- **操作**：行 → 停用 → 确认弹窗（说明"该用户将无法登录，当前会话立即失效"）→ 确认；停用后同一入口变为"启用"
- **反馈**：成功 → toast + 状态列更新
- **验收**：停用后该用户旧 token 失效（登录被拒）；启用后恢复

### 3.5 重置密码

- **入口**：行 → 重置密码 → 确认
- **反馈**：弹窗展示临时密码（仅此一次），提示"请线下告知，建议首次登录后修改"
- **边界**：重置后该用户全端失效（token_version+1）
- **验收**：临时密码可登录；旧密码/旧 token 均失效

## 4. 客户管理

### 4.1 客户列表（web 完整 / mobile 精简）

- **入口**：web 侧边栏·客户 / mobile Tabbar·客户
- **web 列**：名称 / 城市 / 等级 / 状态 / 负责人 / 最近活动
- **操作**：搜索（名称/城市，防抖 300ms，五级排序）、筛选（等级/状态）、分页
- **权限**：登录可见列表；`customer.write` 才显示"新建客户"
- **边界**：查重/搜索可命中权限外客户，但只显示最小标识（名称+城市），点击详情走权限（§7.3）
- **反馈**：三态统一；行点击进详情
- **验收**：五级检索排序正确；权限外客户只显最小标识

### 4.2 新建客户（走查重管道）

- **入口**：列表 → "新建客户"
- **字段**：名称（必填，可地址式）、联系人电话（**至少一个，可无名**）、地址（软建议）、产业/应用/类型/来源/产品线（字典）、负责人（默认本人，可指定他人）
- **查重流程**（§8.2 五步管道）：
  1. 硬拦截：商号 key/编码/信用代码重复 → 409"已存在"，禁止继续
  2. 疑似提示：置信度高 → 醒目提示 + "申请接管"；中 → 普通提示；低 → 弱提示
  3. 用户可选"继续新建"或"查看疑似客户"；忽略动作留审计
- **边界**：口语名+无地址无电话 → 软提示"信息不完整，可能无法识别重复"（不拦截）
- **反馈**：成功 → 跳详情页
- **验收**：硬拦截不可绕过；疑似提示置信度分级正确；查重命中权限外客户可申请接管

### 4.3 客户详情

- **内容**：基本信息、联系人列表、活动时间线（拜访/商机/客诉按时间聚合）、归属信息（负责人/建档人/登记时间）
- **操作区**（按能力点显隐）：记一笔拜访 / 新建商机 / 登记客诉 / 编辑 / 移交 / 接管申请 / 释放
- **权限**：`customer.write` 才能操作；只读角色（assistant）仅查看
- **验收**：详情聚合三类活动时间线；无权限操作不渲染

### 4.4 编辑客户

- **入口**：详情 → 编辑
- **可改**：名称 / 地址 / 字典字段（产业/类型/来源/产品线）/ 备注
- **校验**：名称改动较大时建议复走查重（后置可选）
- **反馈**：成功 → toast + 详情刷新
- **验收**：编辑后详情与列表同步更新

### 4.5 联系人管理

- **操作**：详情 → 联系人 → 添加/编辑/删除
- **字段**：姓名（可空=裸电话）、职务、电话（脱敏展示 138\*\*\*\*1234）、是否首要联系人（每客户至多 1 个）
- **校验**：每客户至少一个联系人电话（记录级约束，应用层校验）
- **验收**：脱敏规则正确；首要联系人唯一

### 4.6 归属治理（所有权）

| 操作         | 入口            | 规则                                                  | 反馈                        |
| ------------ | --------------- | ----------------------------------------------------- | --------------------------- |
| **移交**     | 详情 → 移交     | owner 本人/管理链/admin；容量校验；同事务五步（§8.3） | 确认弹窗 → 成功 toast       |
| **接管申请** | 详情 → 申请接管 | 非 owner 可发起；已有 pending 不可重复                | 成功 toast → 接管审批列表   |
| **释放**     | 详情 → 释放     | 本人 owner；**有未解决客诉拦截**；去向=公海/无效      | 确认弹窗（说明后果）→ toast |
| **认领**     | 公海列表 → 认领 | 状态 public；容量校验                                 | 成功 toast → 进自己名下     |

- **验收**：释放遇未解决客诉被拦截；接管走审批流；归属变更后子实体当前归属跟随

## 5. 拜访登记（P0 主场景）

### 5.1 拜访表单（mobile 主场景 / web 同构）

- **入口**：客户详情"记一笔拜访" / 移动"记一笔"Tab / 销售日志快捷入口
- **字段**：客户（必填，选择器+内联建档）、沟通时间（默认当前，可改）、方式（线下拜访/远程/其他）、类型（新客户/存量维护/行业关系）、生意情况 / 设备使用 / 人员变动、下次拜访日期（可选）+ 下次动作
- **校验**：客户必填（客户旅程原则）；`customerId/occurredAt/method` 必填
- **联动**：填了下次拜访日期 → 自动生成周计划项（强一致，同事务）
- **边界**：内联建档（选不到 → 表单内快速建客户，走查重管道，一个流程不跳出）
- **反馈**：成功 → toast + 返回并刷新时间线/列表
- **验收**：填下次拜访后周计划出现对应计划项；内联建档不打断流程

## 6. 商机闭环

### 6.1 商机列表（web）

- **列**：客户 / 商机名称 / 阶段 / 意向金额 / 负责人 / 下次跟进日期（逾期标红）
- **操作**：搜索（客户/名称）、筛选（阶段/金额区间）、分页
- **逾期**：`next_follow_up_date` 过期 → 待办标记（红点/置顶），点进去用推进或结案处置
- **验收**：逾期商机在列表/待办可见

### 6.2 新建商机

- **入口**：客户详情"新建商机" / 商机列表"新建"
- **字段**：客户（必填）、名称、来源（字典）、产品线（可选）、意向金额（类型+金额，必填）、需求发现日、预计成交日、下一步动作+日期（必填）
- **反馈**：成功 → 跳详情
- **验收**：意向金额与下一步必填拦截

### 6.3 商机详情与推进

- **内容**：基本信息、事件时间线（created/stage_changed/updated）、推进操作区
- **操作**：推进（结论+下一步，可转订单）、结案（丢失/需求消失，必填原因）
- **状态机**：intent → following → ordered(生成 Deal) / lost / demand_disappeared（§8.5）
- **反馈**：转订单 → 生成 Deal 并提示；结案 → 确认弹窗（说明不可恢复）
- **验收**：状态机流转正确；转订单幂等生成 Deal；结案原因必填

## 7. 客诉闭环

### 7.1 登记客诉

- **入口**：客户详情"登记客诉" / 客诉列表"新建"
- **字段**：客户（必填）、类型（字典 6 类）、问题描述（必填）、发生时间、下次确认日（必填）
- **联动**：登记 → 触发客户风险告警（异步）
- **验收**：登记成功；风险看板出现该客诉

### 7.2 客诉跟进与解决

- **内容**：客诉详情 + 跟进时间线（只追加）+ 状态（registered/resolved）
- **操作**：跟进（内容必填；FOLLOWED_UP → 下次确认日；RESOLVED → 解决结果必填）
- **边界**：resolved 为终态，**禁止任何跟进**（后端拦截 + 前端置灰）；逾期（未解决且下次确认日过期）→ 风险看板
- **验收**：解决后跟进入口置灰/拦截；逾期客诉进风险看板

## 8. 费用（轻量统计）

- **入口**：web 侧边栏·费用 / mobile"记一笔"
- **字段**：费用日期（默认今天）、五类分项金额（烟酒/礼品/餐叙/招待/住宿）、备注

## 9. 周计划 / 接管审批 / 字典配置

### 9.1 周计划（web 完整 / mobile 查看+简单反馈）

- **入口**：web 侧边栏·周计划
- **内容**：业务周（13 周窗口：近 4 + 未来 8）、按人周计划列表、计划项（日期/客户可选/动作必填）
- **联动**：拜访"下次拜访"自动生成的计划项（来源标注）；执行对比（计划 vs 实际，分列展示，不精确配对）
- **指导意见**：管理者 → 被指导者（红点已读闭环）；author 须为被指导者上级
- **验收**：拜访联动计划项出现；指导意见红点可读后消失

### 9.2 接管审批（`approve.claim`）

- **入口**：web 侧边栏·接管审批
- **内容**：pending 申请列表（客户/申请人/原因/时间）；审批操作（通过/拒绝，拒绝必填意见）
- **规则**：单点审批（候选池任一批准即生效）；禁止自我审批；同客户仅一条 pending
- **反馈**：审批后通知申请人；结果在列表状态更新
- **验收**：通过后客户归属变更；拒绝留意见；并发重复审批被拦

### 9.3 字典配置（`user.manage`）

- **入口**：web 侧边栏·字典配置（admin）
- **维度清单（9 类，§7.2 customer_dimension_options）**：industry 产业 / sub_industry 二级行业 / customer_type 客户类型 / product_line 产品线 / source 客户来源 / complaint_type 客诉类型 / trade_type 交易性质 / opportunity_source 商机渠道 / visit_type 拜访类型
- **列表**：维度下拉切换（切换即按维度过滤）+ 选项表格（名称/排序/状态）+ 三态（加载/空/错误）
- **新增**：当前维度下加选项（名称必填、维度内唯一）
- **编辑**：改名称 / 排序号
- **启停**：停用不影响历史（字符串快照）；下拉不再出现停用项
- **校验**：维度内名称唯一（冲突提示）
- **验收**：切换维度正确过滤；改名称后下拉实时更新；历史不受影响

> 实现现状：下拉仅 5 类且切换不生效（listAllOptions 全量显示）——按本节点补齐 9 类 + 按维度过滤
