# Lite CRM 文档体系与复用方法

> 本页是 `docs/` 的入口。文档的首要目的不是记录开发过程，而是沉淀一套可以指导设计、开发和验收的 CRM 项目基线。

## 1. 规范型设计基线

| 文档                             | 回答的问题                           | 修改条件                           |
| -------------------------------- | ------------------------------------ | ---------------------------------- |
| `CRM立项PRD-M0-M5冻结版-V0.1.md` | 本次开发边界、优先级与验收截止线     | 开发范围边界或验收条件变化时       |
| `重构架构决策与实施蓝图.md`      | 目标模型、架构约束和建设节奏是什么   | 业务语义、数据模型或技术决策变化时 |
| `PRD.md`                         | 用户要完成什么、规则和验收标准是什么 | 业务规则、页面能力或验收口径变化时 |
| `交互设计打磨.md`                | 功能如何呈现、页面如何衔接           | 关键流程或交互模式变化时           |
| `技术打磨清单.md`                | 实现必须通过哪些通用质量门禁         | 质量标准或验证方法变化时           |
| `测试体系与编写指南.md`          | 如何验证实现                         | 测试策略、命令或测试分层变化时     |

这些文档统一采用规范式写法：直接陈述“系统应当如何工作”，不在正文中穿插“本批已完成”“等待迁移”“当前代码缺失”等开发日志。设计发生替代时直接修订有效结论，由 Git 保存变化历史。

## 2. 实施证据与历史材料

`M0-M5模型收口实施记录.md` 只承担当前项目的迁移、测试和提交证据，不是目标设计来源，也不直接复制到下一项目。

以下文件用于追溯立项讨论或外部调研，不要求随代码更新：

- `工业设备销售全过程CRM建设蓝图及项目立项方案-V0.1.md`
- `工业设备销售全过程CRM项目立项汇报-V0.2.md`
- `工业设备销售全过程CRM建设方案纲要-V0.3.md`
- `工业设备销售全过程CRM立项简报-V0.4.html`
- `M0-工程骨架说明.md`
- `B2B-CRM全球代表产品与移动端体验调研.md`

如需修订管理层材料，应产生明确的新版本；外部调研有新的证据时单独形成新调研基线，不能用实现状态反向改写原始调研结论。

## 3. 在类似项目中的使用顺序

1. 用调研材料和立项方案明确业务矛盾、建设边界与阶段目标。
2. 用 PRD 固化角色、业务流程、对象、规则和验收口径。
3. 用架构蓝图把业务事实、当前状态、未来行动、权限和事务边界落成模型。
4. 用交互设计把模型映射为用户可执行的页面流程，避免用户直接面对数据表结构。
5. 用技术清单和测试指南设置质量门禁，再进入编码和验收。

新项目复制规范型文档后，替换业务背景、角色、对象和约束即可；实施记录、旧版本立项稿和本项目测试结果不复制。

## 4. 同步规则

代码变更后只检查它是否改变了设计事实：

1. 业务语义或数据模型变化，修订架构蓝图。
2. 用户行为、业务规则或验收标准变化，修订 PRD。
3. 页面流程或交互模式变化，修订交互设计。
4. 质量标准或测试方法变化，修订技术清单或测试指南。
5. 仅实施进度变化，不修改规范型文档；由 Git、测试报告和实施证据记录。

Git 是版本事实源，规范文档不维护手工版本流水账。
