# 技术打磨清单（实现层 · M0–M5 收尾）

> **定位**：实现健壮性/缺陷类打磨（状态反馈、数据一致性、危险操作确认等），**与 PRD 的交互设计分开**。
> 逐条打勾；每条给出"现状 → 改法"。

## 1. 状态反馈（错误态 / 空态）

- ☐ **错误态全缺**：`useQuery` 暴露了 `error`，但页面普遍不接（如 CustomersPage 只拿 `data`/`loading`）→ 接口失败静默白屏。
  **改法**：建共享组件（web `AppError` / mobile 对应）+ 逐页解构 `error` 并展示（含"重试"按钮调 `reload`）。
- ☐ **空态全缺**：列表无数据时空白表格。
  **改法**：共享 `AppEmpty` 组件（el-empty / van-empty + 文案），所有列表页接入。

## 2. 数据一致性（写后刷新链路 · 红线 11）

- ☐ **返回刷新抽查**：`router.back()` 依赖组件重建触发 `useQuery` 重新加载，主链路未验证。
  **检查清单**：新建客户 → 列表；拜访/商机/客诉提交 → 详情时间线；作废 → 列表。全部真机走一遍，确认数据闭环。
- ☐ 同一路由内写操作（如详情页编辑）→ 必须 `reload()`/`setData()`，不能靠刷新页面。

## 3. 危险操作确认

- ☐ 费用**作废**、客户**释放**、商机**结案**、用户**停用** → 统一确认弹窗（ElMessageBox / van-dialog），说明后果（不可恢复/数据剔除等）。

## 4. 提交链路健壮性

- ☐ 所有提交按钮 loading + 防重复提交（mobile 表单已达标，web 表单抽查）。
- ☐ 校验失败 → 内联提示 + 定位到第一个错误。

## 5. 会话与错误处理

- ☐ 401 / token 过期 → 统一跳登录（记录来源页，登录后回跳）。
- ☐ 网络异常 / 5xx → 统一错误提示（不裸奔异常堆栈）。

## 6. 细节

- ☐ 长列表性能：表格虚拟滚动（若数据量大）——可后置。
- ☐ 金额/日期格式化统一（domain 层工具，双端共用）。
