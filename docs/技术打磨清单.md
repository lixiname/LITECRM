# 技术质量门禁清单

> **定位**：用于 CRM 项目进入试用、导入正式数据或扩展管理看板之前的实现验收。清单陈述长期有效的质量标准，不记录某次开发批次的完成进度；项目执行证据由测试、Git 和实施记录保存。

## 0. 业务模型门禁

- [ ] **报价与成交分离**：商机允许口头报价 0..N、正式报价 0..N；报价只追加事实，只有明确成交命令生成唯一 Deal。
- [ ] **未来行动只有一个事实源**：拜访、商机和客诉可以在同一事务中产生或更新 `follow_up_actions`；周视图、待办和管理视图不复制计划明细，周视图仅按发生时间聚合实际事实。
- [ ] **历史事实不覆盖**：拜访、商机跟进、报价、客诉跟进和等级变更只追加；主表只承担当前状态快照。
- [ ] **分级概念单一**：S/A/B/C 只表达客户价值等级；名额按“负责人 × 客户等级”计算，并在同一事务内锁定、校验和占用。
- [ ] **客户硬唯一与疑似重复分离**：ERP 客户编码、统一社会信用代码为可空硬唯一键；归一化名称只用于候选检索，不能作为硬唯一约束。
- [ ] **并发更新可检测**：所有可变聚合使用版本条件更新，旧版本写入返回 409；只追加事实不伪装成可编辑聚合。
- [ ] **派生指标可重算**：首次拜访、首次成交、最近活动等字段必须有明确投影、补偿和全量重算路径，否则不得进入管理统计。

## 1. 页面状态

- [ ] **加载态**：首屏、局部刷新和提交过程有明确反馈，不允许用户重复触发同一写操作。
- [ ] **空态**：列表和时间线无数据时展示业务化说明及可执行入口，不呈现空白容器。
- [ ] **错误态**：请求失败显示原因、重试入口和安全退路，不白屏、不吞错、不向用户暴露异常堆栈。
- [ ] **权限态**：无权限操作不渲染；直接访问受限路由或接口时仍由服务端拒绝。

## 2. 写后数据一致性

- [ ] 新建客户后，客户列表和详情能立即看到新记录。
- [ ] 拜访产生下一行动后，客户记录与行动周视图同时可见且只存在一条行动事实。
- [ ] 商机跟进、报价、成交或结案后，详情、列表、行动和漏斗口径一致。
- [ ] 客诉继续处理或解决后，时间线、当前状态和剩余行动一致。
- [ ] 同一路由内写操作使用 `reload()`、缓存失效或显式状态合并，不依赖整页刷新。
- [ ] 返回来源页后保留筛选、分页和滚动上下文，并刷新可能变化的数据。

## 3. 影响性操作

- [ ] 删除、停用、作废、释放、结案等终态操作必须说明影响范围并二次确认；销售计划只开放改期和原子替换，不开放裸取消。
- [ ] 不可逆操作与普通主操作在位置、颜色和文案上明确区分。
- [ ] 业务规则拦截返回可理解的原因和处置建议，例如未解决客诉阻止客户释放。
- [ ] 批量操作必须预览命中数量、失败策略和可恢复方式。

## 4. 表单与提交链路

- [ ] 必填、格式和跨字段规则在提交前校验，并定位到首个错误字段。
- [ ] 提交按钮具有 loading 与防重复提交；服务端关键命令具备幂等或唯一约束保护。
- [ ] 时间、金额和枚举在双端使用同一语义与格式化规则。
- [ ] 表单失败后保留用户输入；成功后给出反馈并回到明确的业务上下文。

## 5. 会话、网络与安全

- [ ] 401 统一清理失效会话并跳转登录，登录后可安全回到来源页。
- [ ] 403、404、409 和 5xx 分别提供符合业务语义的反馈，不能统一显示“操作失败”。
- [ ] 网络超时和断网提供重试；重复重试不会制造重复客户、报价、成交或行动。
- [ ] 日志不记录密码、令牌和不必要的客户敏感信息。

## 6. 数据库与迁移

- [ ] 每次结构变化都有可审阅迁移，不使用运行时自动同步替代迁移。
- [ ] 删除旧字段或表之前先完成数据转换、数量核对和异常数据处理。
- [ ] 约束、索引、外键和事务边界与业务不变量一致，不能只依赖前端校验。
- [ ] 迁移在包含历史数据的副本上验证；失败必须整体回滚或给出明确恢复步骤。

## 7. 性能与可维护性

- [ ] 列表查询具有分页和必要索引；管理聚合避免逐行 N+1 查询。
- [ ] 大型前端依赖按路由或业务模块拆分，首屏包体和弱网体验达到项目目标。
- [ ] Service 按业务职责拆分；事务边界和关键 SQL 保持可见，不制造万能 Service 或无意义 Repository。
- [ ] OpenAPI、共享类型、数据库迁移、实现和测试在同一变更中保持一致。

## 8. 发布前主链验收

- [ ] 登录 → 建客户 → 查重确认 → 记录拜访 → 生成下一行动。
- [ ] 执行行动 → 建商机 → 多次跟进 → 多次口头/正式报价 → 报价后行动。
- [ ] 客户明确下单 → 唯一成交；或明确丢失/需求消失 → 结案并处理剩余行动。
- [ ] 登记客诉 → 多次处理 → 解决；未解决客诉按规则阻止客户释放。
- [ ] 客户移交、接管、认领和释放时，当前归属、未完成行动与历史责任快照保持正确。
- [ ] Web 与移动端对相同业务对象呈现一致结果，差异只体现在交互形态。
