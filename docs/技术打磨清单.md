# 技术打磨清单（实现层 · M0–M5 收尾）

> **定位**：实现健壮性/缺陷类打磨（状态反馈、数据一致性、危险操作确认等），**与 PRD 的交互设计分开**。
> 逐条打勾；每条给出"现状 → 改法"。
> **清单版本：T1.3（2026-08-26）**；完成证据见 `docs/M0-M5模型收口实施记录.md`。模型层首批阻断项已完成运行验证，清单重心转入交互闭环和实现健壮性。

## 0. 模型层阻断项（先处理，完成前不扩管理看板/不导正式数据）

- ☑ **报价与成交已分开**：`opportunity_quotes` 支持口头/正式各 0..N 次，报价只追加事实；只有独立 `/win` 命令生成唯一 Deal，`source_opportunity_id` 必填唯一约束已完成迁移并通过主链测试。
- ☑ **下一步行动已收为单一事实源**：拜访/商机/客诉在同一事务中写 `follow_up_actions`；旧字段和 `weekly_plan_items` 已完成保留式迁移，周视图只查询行动并返回更早逾期，M3/M4 测试通过。
- ☑ **分级概念冲突已收口**：S/A/B/C 仅保留为客户等级；名额按“负责人 × 客户等级”统计，默认配置、个人覆盖、事务内并发校验和改级历史已落地。
- ☐ **更新时间/乐观锁尚未全覆盖**：客户、联系人、归属、接管、商机、客诉与行动已做条件更新；拜访/商机跟进/客诉跟进改为只追加；费用等剩余可变聚合仍待收口。
- ☑ **归一化名称硬唯一已移除**：`normalized_key` 只用于候选、相似度与检索；硬唯一只保留 ERP 客户编码/统一社会信用代码。
- ☐ **派生字段无维护者**：`firstVisitedAt/firstDealAt/lastActivityAt` 已存在但没有可靠更新与重算路径。
  **改法**：建立可重放投影或暂不使用这些字段；完成前禁止进入管理统计口径。

## 1. 状态反馈（错误态 / 空态）

- ☐ **错误态全缺**：`useQuery` 暴露了 `error`，但页面普遍不接（如 CustomersPage 只拿 `data`/`loading`）→ 接口失败静默白屏。
  **改法**：建共享组件（web `AppError` / mobile 对应）+ 逐页解构 `error` 并展示（含"重试"按钮调 `reload`）。
- ☐ **空态全缺**：列表无数据时空白表格。
  **改法**：共享 `AppEmpty` 组件（el-empty / van-empty + 文案），所有列表页接入。

## 2. 数据一致性（写后刷新链路 · 红线 11）

- ☐ **返回刷新抽查**：`router.back()` 依赖组件重建触发 `useQuery` 重新加载，主链路未验证。
  **检查清单**：新建客户 → 列表；拜访→行动；商机跟进→多次报价→明确下单；客诉处理→下一行动；作废/结案 → 列表。全部真机走一遍，确认数据闭环。
- ☐ 同一路由内写操作（如详情页编辑）→ 必须 `reload()`/`setData()`，不能靠刷新页面。

## 3. 危险操作确认

- ☐ 费用**作废**、客户**释放**、商机**结案**、用户**停用** → 统一确认弹窗（ElMessageBox / van-dialog），说明后果（不可恢复/数据剔除等）。

## 4. 提交链路健壮性

- ☐ 所有提交按钮 loading + 防重复提交（mobile 表单已达标，web 表单抽查）。
- ☐ 校验失败 → 内联提示 + 定位到第一个错误。

## 5. 会话与错误处理

- ☐ 401 / token 过期 → 统一跳登录（记录来源页，登录后回跳）。
- ☐ 网络异常 / 5xx → 统一错误提示（不裸奔异常堆栈）。

## 6. 细节

- ☐ 长列表性能：表格虚拟滚动（若数据量大）——可后置。
- ☐ 金额/日期格式化统一（domain 层工具，双端共用）。
